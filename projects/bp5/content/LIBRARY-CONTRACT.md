# Guided library contract 2.0

`library.json` adds 18 situations and 54 missions. `scenarios.json` and its three original IDs remain unchanged. Keep every legacy session's frozen scenario, framework and evidence. Never upgrade an old attempt to the new guided state machine in place.

Each situation contains exactly three missions with distinct communication goals. `progression.order` recommends a sequence; it is not an ability ranking or prerequisite. All missions remain accessible. A repeat is a new attempt with a new history, even when the same branch is chosen. The recommendation to try another branch or reduce hints is practice, not a mastery claim.

Each mission extends the previous scene's reading/listening/writing/phrase/recall fields. `learner_brief_en` describes the fictional facts needed for this task so required information is not hidden. `response_guidance_en` explains the limited guided recognition. `opening_en` translates the character opening. `steps[].prompt_en_kind` distinguishes task guidance from a literal translation; final confirmation questions now have English translations. Their `meaning_en` labels state concrete meanings such as paying by card or preferring cash, including the context of repeated questions such as “Does that work?”.

`start_step` references `steps[].id`. Each step has an objective ID, user-facing objective label, authored prompt, clarification and phrase help. Every intent has accepted examples, required word/phrase groups, rejected terms, a complete Swedish reply, a material branch label and `next_step`. Deliver `reply_sv` exactly once: it already includes the next character question. Do not append the next step prompt a second time.

Recognition normalizes Unicode/case and matches complete word or phrase boundaries. Each intent may have `exact_replies_sv`: these require equality of the entire normalized token sequence. This explicitly authored route can include meaningful negative sentences, such as declining Friday while proposing another day. It is not substring matching and extra contradictory text cannot be appended. Otherwise, every `required_groups` group needs a match and any `reject_terms` match blocks that grouped route. Zero or multiple matching intents means clarification, not advancement. Intents may be exact-only, with empty required groups; final confirmations deliberately use this form so an unrelated sentence starting with “Ja” cannot finish a task. Finite inflection dictionaries enumerate reviewed forms; no automatic stemming is used.

`meaning_sv` and `meaning_en` describe the intended reply for an explicit meaning-clarification interface. Final replies also include `reference_question_sv` and `outcome_scope: final_followup_only`: declining map help, a new cup, written instructions or card payment does not automatically cancel the earlier substantive choice. A manual meaning selection must remain declared supported practice, retain the original learner input, and never be relabelled as an independently recognised spoken performance. The content schema supplies these meanings; it does not itself implement the recovery interface.

The matcher still rejects many valid, unseen Swedish paraphrases. The fresh independent 36-case diagnostic accepted only 2 of 18 valid replies while rejecting all 18 unsafe/uncertain replies. A finite inventory is not broad language comprehension. A transparent meaning-clarification route is necessary for a usable guided product; unsupported language must not be labelled incorrect or reduce an ability score.

Record the matched intent ID, objective, help exposure, input provenance and immutable version. Terminal `next_step: null` completes a task only when all `completion_objectives` have been reached on that attempt. Turn count and elapsed time never complete objectives. Every authored branch is reachable and each terminal path covers the required objectives. Basic tasks have three accepted turns; Medium adds a reason/clarification; High adds five substantive discussion turns for eight in total. Actual duration varies. The high mode is explicitly a guided discussion; it is not unrestricted generative brainstorming.

All runtime character replies and task feedback are authored. Basic and Medium must never fall back to a generative model. Do not silently use one for guided High either. Legacy experimental conversation, if available, remains visibly separate.

Each mission has a different reading and listening stimulus. Their `context_en` explains that these are separate messages in the same setting, not transcripts of the learner's chosen branch. Writing prompts permit the actual chosen, declined or unresolved outcome. Listening text remains hidden until the learner responds; revealing it makes listening unassessed. Edited ASR does not establish oral content; typed text does not establish speaking; dictation does not establish independent writing. Completion records `practised`, not a reviewed successful skill observation. Independent practice is not mastery. Keep hints, replays, English assistance and original provenance visible.

The library maps partial task opportunities to `curriculum.json` criteria and preserves that file's official references. It does not cover a whole SFI course, national exam readiness, pronunciation evaluation or foundational literacy. Current A writing is deliberately not mapped to these composed-message tasks because its actual criterion concerns personal details/copying. Guided high tasks do not establish all free-discussion or formal-situation requirements. An SFI educator has not validated the mappings.

Run `python content/library_builder.py`, then `python content/library_heldout.py`, then `python content/validate_library.py` from the project directory. The first separate evaluation found and fixed two missing variants and an off-topic colour match; this history means those cases are now regression fixtures. Backend tests must use its real matcher against `library_evaluation.json` rather than rely only on the content validator. A pass is engineering evidence, not a native-speaker or learner-effectiveness evaluation.

The broader repair corpus is `natural_reply_evaluation.json`; `evaluate_natural.py` preserves before/after counts and individual failures. Its reviewed successful meanings deliberately became `authored_reply_inventory.json`, so it is authoring/regression evidence, not held-out evidence. Of 1,862 case contexts, 683 have distinct text; common confirmation phrases repeat across different branches. Two initial annotations concerned a different task goal and were corrected transparently, with the initial corpus/results retained in `snapshots`.

The independent 108-case set was authored from stripped briefs before inspecting rules. It scored 39/108 on v2, 56/108 on the first v3 repair and 108/108 only after disclosure and repairs. `external_reply_regression.json` and `external_reply_results.json` retain this distinction. The fresh 36-case set subsequently scored 20/36, demonstrating that the regression pass does not establish generalisation. No external Swedish educator or learner-effectiveness validation is claimed.

Content versions 2026-11-01.2 through 2026-11-01.6 remain as immutable JSON snapshots. Version .6 changes only one Swedish character sentence from .5. Version .7 changes learner-facing confirmation meanings, question translations and recovery feedback; matching rules remain identical to .6. Recovery feedback offers choosing the intended meaning before rewording. Existing sessions must keep their original snapshots; new content applies to new attempts. Do not silently rewrite old history or its support/evidence records.
