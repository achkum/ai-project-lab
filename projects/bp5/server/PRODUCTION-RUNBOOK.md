# BP5 production service handoff

The application entry point is `production:app`, not the earlier experimental `app.py`. It requires Python, the pinned packages in `requirements.txt`, one Uvicorn worker, a private writable `LAB_DATA_DIR`, and a restrictive process umask (for example 0077). Example from the lab root: `python -m uvicorn production:app --app-dir projects/bp5/server --host 127.0.0.1 --port 8788 --workers 1 --no-access-log`. Set `LAB_INSTANCE_ID`, `BP5_PUBLIC_ORIGIN` to the exact HTTPS origin, `BP5_COOKIE_PATH=/apps/bp5/`, `BP5_SECURE_COOKIE=1`, and `BP5_ALLOWED_HOSTS=127.0.0.1:8788`. The TLS proxy must strip `/apps/bp5`, preserve the browser Origin, and set Host to the configured loopback Host. Do not enable the old experimental server on the public route. No shared-owner bearer token is used for account authentication.

Create an invitation only from the service host as its service user: `python projects/bp5/server/manage.py create-invite --output /private/new-invitation.txt`. The output path must not exist. The generated secret is written to that file rather than stdout; on POSIX the file is created mode 0600. Transmit it privately, then remove the invitation file according to the host's secret-handling practice. Invitations are one use and expire after seven days by default; the `BP5_INVITATION_TTL_SECONDS` setting is bounded to 60 seconds–30 days. Registration displays eight one-use recovery codes once; a user must save them. While signed in, a user can confirm their password to generate a replacement set; this immediately invalidates every prior recovery code. If both access to the account and all codes are lost, there is no email reset service and an operator-assisted process is necessary. Avoid logging request bodies, passwords, cookies, invite codes or recovery codes. Do not place the SQLite data directory under a public static path.

Production history uses `production.sqlite3`, separate from experimental `bp5.sqlite3`. There is no first-registrant migration. An operator may import explicitly to an existing named account with `python projects/bp5/server/manage.py import-legacy --username NAME --confirm-owner NAME --legacy-db /private/path/bp5.sqlite3`; review the target identity and backup before running it. Imported records remain legacy and read-only through `api/legacy`; export includes them. Import rejects the entire batch if it contains invalid JSON, a record over 128 KiB, or would exceed 200 legacy records; it never partially imports those batches. Deleting all history removes both imported and current records. Minimal hashed request markers are retained until account deletion so a delayed retry cannot recreate deleted history; account deletion removes those markers too. Back up the data directory and SQLite WAL consistently while the service is stopped or via SQLite backup; test restore and retention separately.

Provide Linux executables and models through `BP5_FFMPEG`, `BP5_WHISPER_BIN`, `BP5_WHISPER_MODEL`, `BP5_PIPER_BIN`, and `BP5_PIPER_MODEL`. No LLM runs in mission matching. Audio jobs are one-at-a-time, bounded in size/time, cancellable by their owner, and temporary files are normally removed; after an abrupt process death they may remain until the next startup, which cleans only unlocked workspaces in the exact application audio namespace. Verify executable provenance/licences and Linux operation independently. Run under a restricted service user and sandbox the media decoder; HTTPS, host firewall, backups, support contact, privacy notice and independent security review remain deployment responsibilities. Current tests and Windows synthetic speech checks do not establish Linux/mobile voice performance, native-speaker accuracy, or production readiness.

Run tests using `python -m unittest discover -s projects/bp5/server -p test_production.py -v`. Tests use isolated temporary accounts and an authored fixture; the optional real voice pipeline test requires `BP5_TEST_LOCAL_AUDIO=1` and configured binaries/models. Test the completed authored library separately before launch.

Authentication attempts are stored in a bounded table (50,000 rows maximum; fail closed) with time-based cleanup. An edge rate limit remains necessary; configure trusted proxy/IP forwarding so requests cannot spoof the source address and so one proxy address is not treated as every user.

Each account is limited to ten active login sessions (oldest evicted on a new login) and 60 new mission creations per hour; an idempotent retry does not consume the creation quota. Account-specific hashed creation request markers are capped at 10,000 and removed on account deletion.

History and export stream account-scoped records directly from SQLite, with at most two concurrent streams per service and a 180-second deadline. A synthetic Windows test with 200 near-limit records and two simultaneous 25.99 MB responses measured Uvicorn process-tree RSS increasing from 66.4 to 70.5 MiB; this is not a VPS load test. Export is delivered as a browser download.
