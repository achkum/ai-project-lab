ST6 — Help a small document model find tables in unfamiliar documents
Investigated 2026-11-02 | KEEP | kept_as_investigated_possibility

A table detector trained on scientific papers may miss a table in an instruction manual or financial report. Retraining a whole large parser can be impractical on a laptop.
Example: An annual report uses a borderless table with a shaded heading. The model should locate the table without treating a nearby chart as another table.

What the study would try
Adapt a small part of a released table detector using a limited number of labelled public pages.
Everyday question: How much can a small update help a table detector handle unfamiliar documents?
Expected research output: An adapted table detector and a report on the labels, computer time and document diversity needed.

What was actually checked
Official sources/license and archive-route checks; no detector run or training.
Read 13.08 MB of ZIP directory/sample data and decoded page/category metadata including document name, collection, page number and table class 9. Range success is real; full subset extraction and model runtime are not yet tested. Subsequently extracted a complete 763,103-byte PNG, passed ZIP CRC verification and fully decoded it as 1025x1025 RGB; the selected-member route is demonstrated, while full annotation extraction remains future work.
Model experiments completed: 0. Runtime targets below are planned limits, not measured results.

Qualification and research depth
Kept as an investigated possibility because the scope combines explicit model adaptation with a justified controlled comparison, grouped evaluation and measurable failure trade-offs. Data access and primary terms were inspected. This is a feasibility judgment, not completed model evidence, a novelty claim or LTU approval.
This is a label-budget and domain-transfer study of a pretrained object detector, with document/source grouping, localisation metrics, adapter ablations and explicit compute limits. It uses existing region labels rather than requiring a company archive or new reading-order annotation.

Scientific question and hypothesis
How far can a frozen table detector be adapted to new document categories using a small labelled-page budget and only its output heads or a small query-feature adapter?
A small domain-adapted head will improve table detection on held-out documents beyond confidence-threshold tuning alone, while retaining useful performance on the source-like category.

Data access and rights
DocLayNet
Official public archive supports selective HTTP Range access. Stream COCO metadata and extract selected PNG members, retaining source-document/collection information.
80,863 pages and 11 region classes. Core ZIP 30.01 GB; do not download it in full. Train metadata is 81.8 MB compressed/565 MB uncompressed; a streaming reader plus approximately 1,000–2,000 selected pages is the proposed study footprint.
Terms: CDLA-Permissive-1.0. Preserve dataset provenance/attribution and terms when redistributing enhanced data; code and model terms are separate.
Still to verify: Build a streaming metadata selector, inspect selected images and count table/non-table pages by independent document. Check release duplicates and document category mapping.

Model adaptation
Microsoft Table Transformer table-detection checkpoint, DETR-R18, about 110 MB.
Freeze backbone/transformer and cache query features; train classification/box heads or a small residual adapter with the original matching loss. A limited last-decoder adaptation is optional only if CPU timing permits.
Prefer output-head/query-adapter training; keep cached features and a page-at-a-time pipeline below the memory cap.
Model terms: Model card and official repository declare MIT.

Comparators
- Line/connected-component and word-alignment table heuristics, with limitations stated.
- Unmodified Table Transformer.
- Confidence-threshold calibration and head-only adaptation on exactly the same labelled pages.

Evaluation and leakage controls
Respect official train/validation/test roles and additionally group by source document and collection. Sample label budgets of 16/64/128 development pages without using final test labels. Hold out complete document categories or collections where support permits; all degradations of a page stay together. Distinguish real category transfer from synthetic scan degradation.

Ablations
- Classification-only versus box-head/query-feature adaptation.
- Label budget and document-source diversity.
- Threshold tuning, scan augmentation and source-performance retention.

Measurements
AP50/AP75 and mean AP, table recall at a fixed false-box-per-page budget, small/borderless-table errors, CPU latency and peak RAM. Bootstrap documents/collections, not pages. Table location metrics do not establish cell-text extraction quality.

CPU plan and cheaper fallback
Selective image subset on disk, streaming JSON metadata, frozen inference and cached head fitting. Target below 8 GB RAM, maximum one overnight feature pass and a measured per-configuration CPU limit. Do not run billion-parameter parsers or paid OCR APIs.
Train a calibrated reranker of frozen detector proposals plus simple geometric candidates. Clearly label the reduced scope: it cannot find a table for which no candidate exists.

Closest work and proposed contribution
Table Transformer already supports domain adaptation, and October OmniParseBench highlights separate table/layout slices and strong current parsers. This study asks about constrained adaptation efficiency and retained source performance. It does not invent table detection or claim parity with full modern parsing systems.

Risks and kill test
A frozen detector may not propose missed target tables, limiting head-only improvement. Collection overlap can inflate results. Table localisation alone is insufficient for usable CSV extraction.
Select independent source/target documents with enough table and negative pages; extract and inspect a small licensed subset, then benchmark frozen CPU inference. Revise to proposal reranking if the model's missing-candidate ceiling prevents head adaptation; withdraw if the subset pipeline exceeds feasible storage/runtime.
